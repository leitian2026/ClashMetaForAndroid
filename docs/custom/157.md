## 157. 文档分层：CUSTOM.md 改成索引，详情按编号拆开，加大小和引用检查（r282）
- **起因：** 旧 `CUSTOM.md` 长到约 505 KB / 2730 行，每次改动都往里追加，从不删减，AI 读不完整份文件，容易漏看后面的规则。
- **新结构：** `CUSTOM.md` 只留基线和当前版本、“怎么找”、上游文件总表、构建事实、“本版没做的”、功能一览（每个编号一行）、修改记录表。每个编号的详情在 `docs/custom/<编号补零到 3 位>.md`（#109a 是 `109a.md`，重复的 #115 两段合在 `115.md`）。#156 起的分步流水和 IP 测试审查修正按原文顺序放在 `docs/custom/history/h01…h06`，每个文件不超过约 30 KB。
- **搬运方式：** 逐字搬运，没有改写任何一条内容；上游文件总表原样保留在 `CUSTOM.md` 里（`scripts/check-custom.sh` 和同步上游的步骤都靠它）。`当前版本：` 那一行仍在 `CUSTOM.md` 第 4 行（#40 #44 读它）。代码里的 `CUSTOM.md #N` 注释没有改，编号不变，所以没有碰任何上游文件。
- **以后怎么写：** 改功能时把对应详情文件原地改写成现在的样子，不再在后面追加“rXXX 又改了什么”；新功能新建 `docs/custom/<新编号>.md` 并在功能一览加一行；`history/` 不再追加。这条写进了 `AGENTS.md` 规则 7，开头新增“动手前清单”，回复开头要写“已读：…；要改：#…”。 提交方式：`AGENTS.md` 有“提交方式”一节，直接提交到 `custom`，工具一次只能提交一个文件时允许逐文件提交；规则 5、7 相应放宽。
- **检查（`scripts/check-custom.sh`，#19）：** 原有三项照旧，“新文件有没有登记”改成同时在 `CUSTOM.md` 和 `docs/custom/` 里找文件名，`docs/custom/` 本身不再当作带 `CUSTOM` 标记的代码文件。新增三项：(4) `CUSTOM.md` 不超过 64 KB，`docs/custom/` 下每个文件不超过 40 KB；(5) 代码里每个 `CUSTOM.md #N` / `CUSTOM #N` 引用的编号，都有详情文件或在 `CUSTOM_ARCHIVE.md` 里；(6) `docs/custom/` 下每个文件都在 `CUSTOM.md` 里登记，`CUSTOM.md` 里的每个文档链接都指向存在的文件。`Check Custom` 工作流本来就在推送 custom 分支时跑这个脚本，不需要改工作流。
- **改动文件：** 新增 `docs/custom/` 下全部文件；改了 `CUSTOM.md`、`AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、`.cursorrules`、`.github/copilot-instructions.md`、`scripts/check-custom.sh`。没有改上游文件，上游文件总表不变。 本次规则调整没有新文件，只改了 `AGENTS.md`。
- **功耗 / 运行：** 只有文档和 CI 检查脚本，不进 App，不增加定时器、轮询、监听或网络请求。
