## 168. 网络运营商识别，首页卡片常显

### 行为
- 服务进程启动网络监听时，识别当前 VPN 下方的真实网络；网络签名稳定变化后识别一次。启动入口复用 `NodeIpNotifier.start()` → `NetworkRetest.start()`，不要求 Clash 核心正在运行。
- 移动数据网络优先读取默认数据卡的 MCC+MNC，不发在线请求。API 24+ 使用 `SubscriptionManager.getDefaultDataSubscriptionId()` 和 `TelephonyManager.createForSubscriptionId()`；API 21–23 使用默认 `TelephonyManager`。不新增危险权限；读取失败、没有 SIM 或系统不允许读取时，改用在线识别，并把来源记录为 `online_fallback`，不把 fallback 本身当错误。
- MCC/MNC 归类：
  - 移动：46000、46002、46004、46007、46008
  - 联通：46001、46006、46009、46010
  - 电信：46003、46005、46011、46012
  - 广电：46015
- Wi-Fi、以太网、热点及移动数据 fallback：请求 `https://myip.ipip.net`（纯文本）和 `https://whois.pconline.com.cn/ipJson.jsp?json=true`（JSON）。两次请求都通过 `Network.openConnection()` 绑定 `NetworkIpv6.bestNetwork()` 选出的 VPN 下方非 VPN 网络，不走默认网络 / Clash VPN。连接和读取超时各 5 秒，响应体最多 4KB，带 User-Agent；按响应 charset 解码，无声明时 UTF-8，出现乱码再试 GBK。
- 有效结果必须含公网 IP；排除私网、环回、链路本地、组播、100.64.0.0/10 及文档保留地址。认证页、限流页或非预期响应不能仅凭 HTTP 200 通过解析。
- 在线运营商关键词：联通 / Unicom / CNC；电信 / Telecom / Chinanet；移动 / Mobile / CMNET / CMCC；广电 / Broadcast。无法归类显示“未知”，不单独算网络错误。两接口均有效但运营商不一致时显示未知并记网络错误；只有一个有效时采用单个结果。
- 网络错误：切换后无网络、请求超时、所有接口失败 / 未返回公网 IP、两个接口运营商不一致、绑定底层网络失败。MCC/MNC 读取失败仅作为在线 fallback 来源，不作为错误。
- 失败不重试、不轮询、不提供手动刷新；下一次网络签名变化再识别。相同签名已有缓存时直接复用。
- 息屏时不执行在线请求；保留待识别签名，亮屏后补识别。没有待办时不注册屏幕接收器。

### 首页与诊断
- 首页“运行中”状态卡片移到“当前 IP / 运行中的问题”卡片上方；`custom_issues_card` 仍常显，点击行为不变。
- 无核心问题、无网络错误时标题显示“当前 IP”，副文案显示省、市、运营商；没有缓存时显示识别中，运营商无法识别时显示未知。
- 有问题时标题显示“运行中的问题（N）”，N = 未忽略且未恢复的核心问题数 + 网络错误数。网络错误排在核心问题前，问题摘要最多两条，更多时提示“点此查看全部”。识别到运营商时，另起一行显示“当前 IP 省 市 运营商”（“当前 IP”后不带冒号）。卡片点击仍进入错误与诊断页。
- Clash 未运行时仍读取网络识别缓存并显示卡片；核心问题只在 Clash 运行时查询。
- 状态栏“运行中的问题”通知在问题摘要后追加“当前运营商：运营商名”；网络识别缓存更新或网络断开时，服务端同步刷新已有通知，不新增通知渠道、权限、定时器或轮询。
- 错误与诊断页通过 `ErrorsReport.networkIdentity` / `ErrorsText` 显示网络错误和当前网络识别信息；原有“复制全部”拼接逻辑自动包含该块。
- 跨进程快照放在 `common/.../NetworkIdentityStore.kt`，用 `AtomicFile` 原子写 JSON；服务进程单写，主进程读取。结果更新后复用 `ACTION_ISSUES_CHANGED` 广播，无新增广播接收器。

### 验证与局限
- 已直接提交到 `custom`，未运行 Gradle / Kotlin 编译；用户手动构建并由 Actions 验证。
- 需要设备实测：运营商接口的实际响应格式、接口可用性、绑定的底层 Network 是否确实绕开 Clash VPN、API 24+ 默认数据卡读取是否受设备权限策略限制。未授予 `READ_PHONE_STATE` 时本地 MCC/MNC 可能不可读，会 fallback 在线查询。
- 在线查询两个接口串行执行，最坏约 10 秒，只在启动或真实网络变化后发生；息屏不发请求。识别失败不会在同一网络上自动重试。
