## 158. 已保存 IP 独立直连 / 经节点下载测速及真实进度显示

- **入口与列位置：** 已保存 IP 表左侧只有“IP 地址”列固定；右侧是一个整体横向滚动区域。“直连”与“经节点”两列位于该滚动区域最前面，紧挨固定 IP 列右侧，顺序为直连、经节点，原有其他列整体后移。两列不固定、不并入 IP 固定区。
- **请求：** 复用配置检查页现有 kind=ip、mode=download 下载测速请求，不另建下载实现。直连请求 node 为空；经节点使用配置检查页保存的 ip_node，并先校验节点存在。两种模式分别复用各自下载 URL 偏好。
- **真实进度来源：** Go 下载读取响应体时累计真实字节数，从首字节开始计算已用毫秒；只在距上次上报约 250 ms 时通过现有 native logcat → ILogObserver → Activity 回调通道上报，事件正文只有“已读字节”和“首字节后毫秒数”两个数字。不会逐数据块跨 Binder / JNI。
- **进度计算与显示：** Kotlin 使用 max(已读字节 / 30 MiB, 已用毫秒 / 6000) × 100%，限制 100%。下载中第一行“直连 / 经节点”保持不变，第二行速度数字替换为百分比；按钮背景用 ClipDrawable 从左向右按 level 填充。配置检查页对应测速按钮同样显示百分比。只更新当前下载按钮，不重建表格、不改行高、不改变 updateSavedRowHeight 逻辑。
- **停止与前后台：** Go 在下载结束、失败、取消及前置校验失败时都发出终止事件；最终 JSON 仍作为最终结果返回。进度状态保存在进程内，页面不可见或息屏时不更新 View；重新回到前台时从当前进度状态补画。取消、失败及正常结束都清除进度并恢复原速度文字。
- **旧数据：** 旧 speed 按 testDirect 迁移到 speedDirect 或 speedNode；未测值为 0 / sentinel，不自动发起测速。新增 speedDirectShort / speedNodeShort 两个默认 false 的布尔字段，旧快照缺少字段时不显示不足 30M 提示。
- **互斥与功耗：** 与配置检查页 IP 测试 / 下载测速共享事件驱动互斥；只在用户点击时发起，不用定时器、轮询或后台任务。Go 端节流约 250 ms；Kotlin 不自行计时，不可见 / 息屏不刷新。
- **结果更新：** 测速结束只更新对应行的对应速度按钮及其 Short 标记；标记和值在同一次 Store 写入。若当前启用了该列排序，仅移动现有行 View 到新位置，不重建表格或列宽。Short 状态变化时只重新测量并同步该行左右两侧行高；从 true 变回 false 时行高恢复。
- **布局：** 两列测速按钮各自放在独立容器内；容器占满对应滚动列单元格，按钮居中并与格子边缘留出间距，不直接被整行高度拉伸。默认按钮为 14sp 两行；只有该模式速度大于 0 且 Short=true 时增加第三行“不足30M”，11sp 橙色。第三行不参与列宽扩张，放不下时改显示“<30M”，保持单行。进度填充位于按钮背景下层，不新增控件，不改变行高或边框。
- **代码：** IpDownloadSpeed.kt 共用请求构造；IpSpeedTestCoordinator.kt 管理互斥及当前进度快照；IpDownloadProgressObserver.kt 解析现有 logcat 事件；SavedIpActivity.kt 和 ConfigCheckActivity.kt 接收进度并在前台更新；ClashManager.kt 通过现有 Clash.subscribeLogcat() 和 ILogObserver 转发；ipdelay/iptry_download.go 产生节流进度，conftest/iptest_probe.go 发终止事件；SavedIpDesign.kt、IpTestView.kt 原位更新按钮和 ClipDrawable。
- **验证：** 完成源码静态检查；未运行 Go 测试、Android 编译或真机测速。用户手动构建后需验证真实下载进度、取消 / 失败收尾、息屏暂停及恢复前台补画。
