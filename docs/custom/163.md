## 163. 已保存 IP 上限与整表滚动

- **新保存上限：** `SavedIpStore.MAX_IP_COUNT` 调整为 300。仅当本次保存要新增 IP 且保存后总数超过 300 时拒绝；覆盖更新已有 IP 不算新增。
- **旧数据保留：** 不自动删除或截断已有记录。旧记录即使超过 300 仍可读取、备份、恢复、编辑和删除；普通写入及备份校验不再用新保存上限拦截。旧记录总数降到 299 以下后，才可再新增，新增后最多到 300。
- **提示：** 中英文提示使用同一常量参数，显示 300，说明这是总数上限，原有记录会保留。
- **展开行为：** 正常点击运营商时只更新单个 `expandedOperatorId`，因此其他运营商自动收起。搜索时匹配的运营商仍全部展开，保持原有行为。
- **表格布局：** 已保存页不再使用 `RecyclerView`，使用普通纵向滚动容器。每个展开运营商只创建一张表；IP 列固定在左侧，表头和全部结果行放在同一个横向滚动容器中，不再每行创建独立横向滚动容器。表格单元格、表头、列宽及 IP 单元格继续复用 `IpTestView`。
- **表头吸顶：** 纵向滚动时，在页面顶部显示当前运营商的表头副本；副本的横向滚动与原表格同步，滚出当前运营商表格范围后隐藏。原表格层级保留，不使用定时器、轮询或动画。
- **多选交互修正：** 非多选状态不显示选择框；长按任意当前可见 IP 进入该运营商的多选状态，所有行在 IP 左侧显示 CheckBox，长按行立即勾选；多选状态下点击整行任意位置（包括 IP、时间、结果单元格及空白区域）均可勾选/取消；行内端口详情等单元格点击在多选时不触发，选中行同时显示背景标记。r330 起，多选已激活时点击只同步更新当前行的复选框和背景色，不重建整张表；仅首次进入和取消最后一项退出多选时重建一次，以添加 / 移除复选框列。**多选期间仍严格沿用当前状态筛选、表头筛选和搜索结果，不因进入多选而展开显示该运营商的全部 IP；选择范围仅限当前筛选后可见的 IP。**多选状态下点击未选中的 IP 不再复制地址；退出多选后隐藏所有选择框。CheckBox 自身只触发一次切换，不与整行点击重复触发；保留单运营商选择、最多 20 条及现有批量重测/删除逻辑。
- **其他保留交互：** 搜索、状态筛选、排序、非多选状态下复制 IP、批量重测和批量删除保持原有行为；搜索展开规则不变。原工具栏“落地国家”筛选已由表头列筛选取代。
- **编译约束：** `IpTestView.kt` 的 import 不得重复（Kotlin 2.1 报 Conflicting import）；`SavedIpDesign.kt` 批量重测估算的 `sumOf` 返回值显式标为 `Int`，避免 `if` 两个整数字面量分支造成 `Int` / `Long` 重载歧义。`SavedIpActivity.kt` 用到 `launch`，必须 `import kotlinx.coroutines.launch`（`launch` 是扩展函数，不 import 就是 Unresolved reference）。
- **改动文件：** `SavedIpStore.kt`、`SavedIpDesign.kt`、`IpTestView.kt`、中英文 `strings_custom.xml`、本详情及 `CUSTOM.md`；r330 仅修改 `SavedIpDesign.kt`、`IpTestView.kt`、本详情及 `CUSTOM.md`。
- **验证范围：** 静态核对存储限制仅作用于新增、旧数据写入路径、单运营商展开、整表单滚动及整行点击覆盖所有行内子视图、CheckBox 独立处理、详情点击在多选时被屏蔽，以及 r330 活跃多选时的行级状态更新和进入 / 退出模式的结构性重建；未运行 Android 构建或设备交互测试，未打包，未修改 mihomo。
