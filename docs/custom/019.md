## 19. 自检脚本 `scripts/check-custom.sh`
- 用法：`bash scripts/check-custom.sh`（在 git 仓库里、有 `main` 分支时最准；没有 `main` 分支时用宽松检查）。
- 检查：① 带 `CUSTOM` 标记且存在于上游（`main` 分支里有）的文件，必须在本文件"上游文件总表"里；② 带标记的新文件，本文件里必须提到；③ 总表里的每个文件都还存在、还带 `CUSTOM` 标记（合并时挂钩没丢）。有问题时列出来并返回 1。
- 每次改动后、同步上游后各跑一次。上游文件名、标记写法（`CUSTOM`）变了才需要改脚本。
- **r282 补充（#157）：** 脚本新增三项检查：文件大小上限、代码里 `CUSTOM.md #N` 引用的编号都有详情文件、`docs/custom/` 与 `CUSTOM.md` 索引一致；“新文件有没有登记”改为同时在 `CUSTOM.md` 和 `docs/custom/` 里找文件名。


**超大 Kotlin 文件告警：** 第 6 项检查后会检查 `$files` 中的 `.kt` 文件（排除 `core/src/foss/`），超过 `${BIG_FILE_LINES:-2500}` 行时输出路径和行数。默认阈值为 2500，可通过 `BIG_FILE_LINES` 调整。该告警不修改检查状态、不影响退出码；修改大文件前应沿现有分界先拆出一块再增加功能。当前 `IpTestView.kt` 约 2690 行，预期会触发告警。
