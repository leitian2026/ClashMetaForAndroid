## 156. 已保存 IP 清单（r177，排序规则修正补充）
- **独立存储：** 新增 `SavedIpStore.kt`，使用独立 SharedPreferences `custom_saved_ips`，JSON 保存运营商分组、IP 地址、最近状态、最近测试时间、加入时间和上次使用的运营商 ID；不复用最近一轮 IP 测试结果的 `ip_test_last`。
- **数据结构：** `SavedIpEntry.failStreak: Int = 0` 记录连续不通次数：每次保存测速结果时，不通在原值上加 1，通了归 0；粘贴进来的未测试 IP 保持 0。JSON、备份编码、校验和还原均通过同一序列化模型携带该字段，旧保存数据和旧备份缺字段时按 0 读取。内置运营商固定 ID 为 `telecom`、`unicom`、`mobile`，初始空清单包含这三个内置运营商；内置名称留空，由字符串资源提供。运营商删除后，存储规范化不会自动补回已删除的内置运营商；自建运营商保存独立 ID 和名称。IP 状态仅为 `UNTESTED`、`REACHABLE`、`UNREACHABLE`。`countryCode` 保留 IP 登记国家（`row.geo`）；`exitCountryCode` 独立保存 `row.country`（落地国家），两者不混用。旧 JSON 缺少 `exitCountryCode` 时默认为空字符串，不迁移、不自动写回。每条 IP 另存 `lastTestedAt`（最近测试时间，Unix 毫秒）和 `addedAt`（加入时间，Unix 毫秒）；旧 JSON 缺少字段时默认按 0 读取。
- **读写与缓存（本次更新）：** `custom_saved_ips` 仅由 `SavedIpStore.kt` 访问；所有本地修改经 `write()`，`update()` / `saveRows()` / `restoreBackup()` 最终也调用它。Store 按进程内 `dataVersion` 缓存最近一次解析并 `normalize` 的 `SavedIpSnapshot`：版本未变时直接返回同一只读快照，不再访问 SharedPreferences、反序列化或规范化，也不复制整份列表。成功写入时先用本次已规范化的对象替换缓存，再递增版本并记录缓存版本；不依赖 `apply()` 异步落盘，避免读回旧值。快照及条目均为只读 data class / List，调用方只读或通过 `copy()` / 新集合生成修改结果，不原地修改缓存对象。备份编码可直接读取持久化值，备份恢复仍统一走 `write()`。读取损坏时只在实际解码失败那次记录一次 `readError`，缓存命中不重复记录；`takeReadError()` 仍由原页面消费并清除。版本号仅在进程内，不改变 JSON / 备份格式。
- **首次打开异步加载（本次更新）：** `SavedIpActivity` 先创建并显示工具栏和页面框架，再在页面处于前台时通过 `Dispatchers.IO` 调用 `readVersioned()`；完成后回到主线程填充列表。读取期间列表区域留空，不阻塞点击。Activity 在 `onStop()` / `onDestroy()` 取消读取任务；页面实例、销毁状态均再次校验，防止结果写入已销毁页面。若读取与显示之间发生写入，按版本不匹配丢弃旧快照并从最新缓存刷新。返回前台时未完成的首次读取会重新启动；不预热、不轮询、不新增定时器。后续所有 `read()` 调用（已保存页、配置检查页和运营商名称校验）共享同一缓存。
- **筛选与搜索状态（r304 更新）：** 状态标签“全部 / 通 / 不通 / 未测试”直接显示在各运营商标题行，四项单选互斥；默认选中“全部”，选择其他状态后只显示对应状态，再点“全部”恢复显示该组全部 IP。每组状态选择互不影响。表头各文字列筛选也按运营商独立保存；不同列 AND、同列多选 OR，并与该组状态筛选及 IP 搜索按 AND 组合。重测时若 row.country 为空，保留该条目原有落地国家代码。状态、表头筛选、速度排序、搜索关键词、搜索展开状态和已展开运营商 ID 统一由 SavedIpFilterState.kt 管理，并通过 Activity 实例状态保存与恢复。搜索图标 / 输入框位于页面标题行右侧；输入框内清除按钮只清空关键词，关闭按钮只收起搜索并保留关键词。搜索只匹配 IP 地址并忽略大小写。
- **分组与空列表（r304 更新）：** 分组标题显示当前筛选和搜索条件下实际展示的 IP 数量；全部 / 通 / 不通 / 未测试数量按该运营商全部保存项统计，并以可点击的彩色标签显示，选中状态有高亮。展开箭头点击区域至少 48dp，三点菜单区域为 48×48dp；点击三点只打开菜单，不触发展开 / 收起。多选模式继续显示所选运营商的完整 IP 清单，绕过状态、落地国家和搜索过滤。过滤后没有结果时通过 RecyclerView 的 `SavedIpListRow.Message` 显示“没有符合条件的 IP”；原本没有保存 IP 时显示空清单提示。相同列表数据不重复触发全量刷新，窗口重新获得焦点时仍会安全调用渲染。
- **状态恢复：** 搜索关键词、搜索展开状态、各运营商多选状态、各运营商表头筛选、速度排序和已展开运营商 ID 均由 `SavedIpFilterState.kt` 保存；弹窗属于临时 UI，不写入实例状态。恢复搜索展开状态时恢复搜索框显示，不主动弹出键盘。
- **边界：** 不同运营商允许保存相同 IP；同一运营商内按地址去重。每个运营商按 `lastTestedAt` 从新到旧排列；未测试项（时间为 0）排在测试项之后，并按 `addedAt` 从新到旧排列。旧数据缺少时间字段时均按 0 处理，不崩溃；旧未测试项无法还原真实加入时间时保持原有相对顺序。全清单最多 5000 条，写入超过上限时拒绝，不静默截断。读取时补齐三个内置运营商，固定 ID 不依赖本地化名称。

- **当前页面实现（r304）：** 页面顶部只保留标题行和右侧搜索；旧“全部”“落地国家”“排序”工具栏整行删除。状态标签位于运营商标题行。速度排序入口位于速度表头；只有速度支持排序，延迟列不排序。搜索收起不清空关键词。整组多选继续绕过普通筛选和搜索；空结果显示无匹配提示。页面状态通过 `onSaveInstanceState` 保存和恢复，不改 Manifest。
- **已保存 IP 表格行样式：** 所有未选中行使用同一个主题 surface 背景，不再交替绘制斑马纹；相邻行之间使用与运营商分组分隔线相同的主题色和 1dp 细线。最后一行不绘制底线；选中行仍保留原有选中高亮。左右固定 IP 区和横向滚动结果区共用相同分隔线及行高。
- **按数据版本刷新（r332）：** Store 成功写入后递增内存数据版本；已保存页记录最后一次渲染版本，`onResume` 仅在版本变化时重新读取并重建。首次创建仍执行一次初始化刷新；页面旋转或主题导致 Activity 重建时只初始化一次，不在同一版本上重复刷新。配置检查页保存 / 重测、撤销删除和备份恢复均经 Store 写入路径使版本变化；`setCanRetest` 只更新操作可用状态，不触发数据刷新。
- **重启后保留筛选与展开状态（r321）：** 在 `onStop` 时将展开运营商、各运营商状态单选、按稳定列名保存的列筛选、速度排序写入 `custom_saved_ip_ui`；仅当序列化状态与上次写入不同时写一次。无 `savedInstanceState` 时从偏好恢复；搜索关键词和搜索框展开状态不持久化。恢复后仍经 `reconcileTableFilters` / `reconcileSelection` 校正已删除运营商或选项。
- **大批量重测请求提示（r319）：** 选中不少于 10 个 IP 时，确认框显示 IP 数和约请求数；取消不启动测试，少于 10 个仍直接启动。估算按每条记录的 `testDirect` / `testTarget` 模式：直连约 16 次（10 次 TLS 尝试、一次 HEAD 证据请求、默认 443 以外 5 个端口握手）；节点 / 目标站模式约 15 次（10 次主探测、出口国家及 ASN 查询、入口节点握手和 HEAD 证据请求）。ECH 查询按域名短期缓存，不重复按每个 IP 计；可选 WS / H3 / MTU 扩展不计入估算。失败或缓存命中时实际请求可能更少，故提示使用“约”。
- **删除后撤销（r318）：** 批量删除、删除不通的、删除较旧的确认后，用页面根 View 显示 `Snackbar.LENGTH_LONG`“已删除 N 个 / 撤销”。待撤销条目及原运营商 ID 只保存在当前 Design 实例内存；撤销通过 `writeSnapshot` 放回原运营商，地址已存在的跳过。Snackbar 消失、页面销毁或下一次成功删除都会使旧撤销失效；不涉及删除整个运营商或单条删除。
- **配置来源变化的局部刷新（r336）：** 比较新旧配置来源映射，按 IP 地址集合找出来源新增、删除或变化的 IP；只重建保存清单中包含这些 IP 的运营商分组，不重建其他分组。Clash 停止或配置来源变空时，旧映射中的 IP 同样进入变化集合并解除置顶 / 来源标签。使用现有 `renderOperator` 路径，保留其他运营商展开状态、搜索、筛选、吸顶表头和横向滚动位置；不增加配置读取次数或网络请求。
- **标出配置中的 IP（r317，更新）：** 已保存页每次进入 `onStart` 时通过现有 `kind=ip, mode=config` 只读接口读取配置 IP 一次，复用 `conftest/iptest_config.go` 的 `readConfigIPs()`；按 `config[].via` 保留来源：`server` 显示“已在 server”，`hosts` / `alias` 显示“已在 hosts”，`dns` 显示“配置解析 IP”。配置来源标记（r328 起）每个来源一个胶囊：浅绿半透明底（日间 `argb(48,46,125,50)`、夜间 `argb(64,129,199,132)`）、蓝字（日间 `#1565C0`、夜间 `#90CAF9`）、圆角 12dp、12sp，宽度随文字，多个来源横向排列；静态，无动画；独立放在 IP 地址下方第二行；原有推荐、测试时间和连续不通提示仍在后续一行；已保存页建行时把 `IpTestRow.inHosts` 置为 false（`savedTableView` 里 `copy(inHosts = false)`），避免 `ipDetails()` 再显示一条灰色的“已在 hosts”，该提示只在 IP 测试结果页显示（r327）。推荐 IP 和配置内 IP 在每个运营商列表中置顶，置顶组内继续沿用当前排序；其余筛选和搜索条件不变。配置未加载、Clash 未运行或读取失败时静默不标；不新增内核接口、不改 mihomo。
- **复制为 hosts（r316）：** 多选快捷操作增加“复制为 hosts”，按当前表格显示顺序把所选 IP 复制为 YAML 行内列表（每个地址均带双引号，IPv6 同样处理），复制后提示数量。沿用最多 20 条的既有限制，不修改多选上限。
- **运营商最快 IP（r315）：** 标题行（折叠时也显示）从该运营商完整保存清单中选择状态为 `REACHABLE` 且 `avg > 0` 的条目，按 `avg` 最小显示“最快 IP　N ms”；不受当前筛选影响，没有符合项则不显示。单行省略，独立限制宽度，不挤压原有状态标签，不发起请求。
- **测试时间与连续失败显示（r310、r312、r313）：** 表格每行的 IP 下方用 13sp 小字显示最近测试时间；综合推荐前三名的橙色“推荐”标签（13sp）放在已测时间前面；连续不通达到 3 次时，在同一行时间文字后追加红色“连续不通 N 次”，不另占一行。距现在超过 7 天（包括已显示日期的时间）使用橙色，7 天以内保持灰色；从没测过的不显示时间。 表格每行的 IP 下方用 12sp 小字显示最近测试时间（`lastTestedAt`），距现在超过 7 天（包括已显示日期的时间）使用 `IpTestView` 现有延迟 150～300 ms 的橙色（`colorWarn`），7 天以内保持灰色；从没测过的不显示。由新增的 `SavedIpTimeText.kt` 计算：不满 15 天显示相对时间，不到 1 分钟 `N秒`、不到 1 小时 `N分M秒`、不到 1 天 `N小时M分`、其余 `N天M小时`；满 15 天显示日期（今年 `M月d日`，往年 `yyyy年M月d日`）；从没测过（`lastTestedAt` 为 0）的 IP 不显示；时间比当前时间晚（手机时钟回拨）时显示“刚刚”。只在建行时算一次，不用定时器，不自己走字，重新进入页面、筛选、排序、刷新后才更新。默认排序仍是最近测试的在前（见上面“边界”）。原来 `SavedIpDesign.kt` 里没人用的 `savedIpElapsedTime` / `savedIpTimeLabel` 已删除，改由 `SavedIpTimeText` 提供。改动文件：`SavedIpTimeText.kt`（新）、`IpTestView.kt`（`savedTableView` 在 IP 单元格里加一行）、`SavedIpDesign.kt`（删死代码）。
- **失败原因精简与详情弹窗（r329，r337 修正）：** 已保存页中测试失败的 IP 不再显示多行内核原文；按现有 `IpTestRow.code` 错误类别及证书、ALPN、取消等明确原因生成一行红色短语，无法识别时仅显示“握手失败”。原有测试时间、推荐和连续不通信息保持不变。点击红色短语使用独立的失败详情回调，以 IP 为标题显示完整原始错误（含实际测试端口）；弹窗正文放入固定最大高度的纵向滚动容器并启用文本选择；再次打开失败详情、重建整页或受影响运营商表格、页面销毁时关闭旧弹窗。点击 IP 仍复制地址，端口详情仍沿用原有弹窗，不改变其行为。失败详情只在建行时生成，不增加请求、定时器或轮询。`IpTestView.ipCell` 增加可选参数，仅已保存表格关闭旧的多行失败详情，其他 IP 测试结果页保持原行为。
- **批量保存对话框：** 每个运营商单选项右侧提供删除按钮；确认时若该组有 IP，提示将同时删除实际数量的已保存 IP，空组不显示数量说明。删除通过 Store 严格读改写，一次删除只写一次；单选列表立即移除该组，被删项原为当前选择时改选剩余第一项。无运营商时，依赖运营商的保存按钮禁用，仍可新增运营商。Store 规范化保留显式运营商集合，已删除分组不会在下次读取时重建。运营商选择变化时重新读取一次 Store，并缓存该运营商已有地址集合；粘贴框文字变化只使用缓存计算，不在输入事件中反复解码整份保存 JSON。解析和可保存数量刷新采用 200 ms 一次性防抖，新输入取消并重排；切换运营商和确认保存时立即刷新。新建运营商写入后使缓存失效并按新选择重新读取；确认保存前重新读取最新 Store，`saveRows()` 仍通过自身的原子读写路径做最终校验。对话框关闭时取消待执行刷新，不增加后台任务或轮询。
