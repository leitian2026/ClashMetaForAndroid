## 99. 测 IP 页面术语统一及下载测速从首字节计时（r115）
- **模式名称：** 将“套入节点”统一改为“经节点”，两个模式按钮分别为“经节点测延迟”和“直连测延迟”。说明明确经节点模式会临时把所选节点的 server 替换为待测 IP / 域名，再经该节点发起测试；同时说明机房、入口运营商、登记国家等信息来源，以及直连额外测试端口和 ECH。
- **下载测速命名：** 只有表格行内下载动作使用“下载测速”；两个模式按钮及延迟探测不称为测速。两个下载地址标签分别说明直连必须使用 Cloudflare 地址、经节点建议使用非 Cloudflare 地址（Worker 访问 CF 站可能较慢并超时）。弹窗说明下载地址只在测试后点击某行“下载测速”时使用，模式按钮不使用下载地址。
- **延迟定义：** 直连延迟称“握手延迟”，定义为 TCP 建连 + TLS 握手；经节点延迟称“经节点延迟”，定义为经节点请求目标网址的总时间（目标网址留空时使用节点自带测试地址）。日志平均值带上对应名称；表格上方说明补充两种定义和延迟波动（成功结果相对平均值的平均偏差）。
- **机房 / 国家 / 目标站：** “机房（城市）”改为“入口机房”；经节点入口机房列头带 *，说明及日志标明它来自对该 IP 的额外直连读取。落地国家替代“落地”；“目标站机房”保留。目标网址标签说明其用于延迟与目标站机房读取；目标站需在 Cloudflare 上才有目标站机房。
- **失败率和端口：** 将界面“丢包率 / 丢包”改为“失败率”，仅改显示文案，内部 Loss 字段与计算不动。经节点模式的端口列显示“-”，说明标明该列原本来源于节点配置、未实际测试；直连端口测试和 iptest_port_none 既有含义保留。
- **对照显示核对：** r309 起“比对照快”列和“对照”提示行已整体去掉（见 #43）；ConfigCheckActivity 直连分支仍显示 ECH 信息，填目标网址时仍显示目标网址信息。
- **下载计时与上限：** 首字节等待上限为 10 秒，使用 context.WithTimeout；经节点时该等待 context 同时覆盖节点拨号和收到首个响应数据字节。收到第一个 body 字节后才启动用户设置的下载时限和前 1 秒跳过计时及速度计算；前 1 秒从首字节时刻起算。下载量和时间上限由“测试其他 IP”弹窗设置，默认 30 MiB / 6 秒，下载量范围 1～200 MiB、时间范围 1～60 秒；空值或无法解析的输入在 Android 端回退默认值，超范围数值夹紧到允许范围；两个输入框失去焦点时自动保存，只有值变化才提示，被夹紧时提示说明原因，取消不影响已保存的值。Go 的 IPRequest.maxBytes / maxSeconds 缺省为 0（使用默认值），并在下载执行前再次夹紧。直连与经节点两种下载调用都使用同一组实际限制。只有已收到数据且请求正常完成、实际文件小于本次实际字节上限时才标记 speedShort；判断使用本次 maxBytes，不再固定比较 30 MiB。已知 Content-Length 小于上限且完整读到声明长度，或自然 EOF 且总量小于上限，均可判定；时间上限截断不标记。通过 context 完成等待与下载超时切换，不新增轮询或显式定时器。
- **失败原因：** 速度格显示“超时”“无数据”、HTTP 状态码或其他错误的前 20 个字符；完整原始原因仍写入实时日志。
- **保留 / 可选项：** 不改延迟、失败率、延迟波动、耗时明细、目标站请求、端口探测、归属信息和 ECH 的计算或请求逻辑；新增 IpTestRow.speedShort / Go JSON speedShort 字段，Kotlin 默认 false，兼容旧快照。第六部分上游通用文案（ip_delay_age_*、errors_* 等）整段跳过，iptest_ref_none 保留原文。第十二条对照显示逻辑按现状核实，无需改动。
- **改动文件：** core/src/main/golang/native/ipdelay/iptry_download.go、core/src/main/golang/native/ipdelay/iptry_download_test.go、core/src/main/golang/native/conftest/iptest.go、core/src/main/golang/native/conftest/iptest_probe.go、core/src/main/java/com/github/kr328/clash/core/model/IpTestReport.kt、app/src/main/java/com/github/kr328/clash/custom/IpDownloadSpeed.kt、design/src/main/java/com/github/kr328/clash/design/custom/IpTestDialog.kt、design/src/main/java/com/github/kr328/clash/design/custom/IpDownloadLimit.kt、design/src/main/java/com/github/kr328/clash/design/custom/IpTestDialogInput.kt、design/src/main/res/values/strings_iptest_limit.xml、design/src/main/res/values-zh/strings_iptest_limit.xml、design/src/main/res/values-zh/strings_iptest.xml、design/src/main/res/values/strings_iptest.xml 和本登记文件；没有改上游文件总表。
- **功耗 / 网络 / 计算量：** 不新增网络请求、定时器、轮询或后台任务；下载测速仍只在用户点击某行按钮时发生。Short 判断只读取本次响应的 Content-Length 和已有读取结果，不额外读数据、不发请求，只做常数次比较。
- **验证：** Build Debug 首次构建发现 Go 表达式跨行写法触发语法错误（iptry_download.go 原第 177–178 行）；已将 Short 条件合并为单行表达式修正。此次修正尚待重新构建验证；Go 测试及真机验证仍未运行。需继续验证首字节 10 秒等待、首字节后 6 秒窗口、首秒跳过、30 MiB 上限及小文件标记、错误原因显示及各模式文案。
