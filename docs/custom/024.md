## 24. 网络切换后自动重测一次，并标明结果新旧（r25）
**效果：** 在 Wi-Fi 和移动数据之间切换、换了一个 Wi-Fi、或 IPv6 出现 / 消失之后，旧网络上的测速结果对新网络没有意义，却会一直留在页面上。现在网络稳定后自动做一次**只测延迟**的测速（内核自带的那种，不做 #1 的逐 IP 测试，也不发国家探测请求）；错误页的"节点测速超时"末尾写"（N 分钟前测速）"，如果网络在这次测速之后又换过，再加一行"这次测速早于最近一次网络切换，结果可能已经不准"。
- **事件驱动：** `NetworkRetest`（服务进程）注册系统的网络回调（`NOT_VPN` + `INTERNET`），收到事件后先等一个**一次性**的 4 秒（`SETTLE_MS`，每来一个新事件重新计时，网络还在起来时不测半截），到点只看一次："VPN 之下那张网络"的特征（`NetworkIpv6.signature()`：哪张网络、什么类型、有没有 IPv6）有没有变，没变就什么都不做（链路属性反复上报很常见）。**特征里不含 IP 地址**：IPv6 隐私地址会不停轮换，那不值得重测。没有定时器，没有轮询。
- **息屏：** 屏幕关着时不测（只会让射频白忙）。变化仍然记下，同时临时注册一个 `ACTION_SCREEN_ON` 接收器，屏幕亮起时测一次并立即注销。#168 的在线网络识别也遵守同一待办机制：息屏不发请求，亮屏后补识别。没有这件事要等的时候，没有注册任何东西。
- **启动：** `NodeIpNotifier.start()` 里多一行 `NetworkRetest.start(app)`（它本来就是"每进程只启动一次"的入口，`DynamicNotificationModule` 和 `ClashManager.queryTunnelState` 已经会调它），所以**没有新增上游文件改动**。#168 复用这个启动点：启动时识别一次当前底层网络，网络签名稳定变化后再识别一次；即使 Clash 未运行，首页读取 `queryTunnelState()` 也会启动服务监听。
- **核心里怎么做：** `queryCustomConnections(SORT_RETEST = 6, "changed")` 只记下"网络变了"的时间；`"run"` 对所有代理组并发做一次 `tunnel.HealthCheck`，立刻返回，全部结束后记下 `testedAt`（`retest.go`；没载入配置时 `recover` 掉，什么都不测）。手动测速（#1 的 `TestGroup`）开头也会记 `testedAt`，所以"几分钟前"对手动测速同样成立。
- **局限：** ① `testedAt` 只记**我们触发的**测速（手动或网络切换后）；url-test 组自己的定时健康检查不更新它，所以显示的时间可能比实际最近一次测速更早，不会更晚。② 没有为"测完了"发通知，页面要点刷新（或下次打开）才看到新结果。③ 代理没运行时没有回调要处理。
- **功耗：** 只有系统网络事件才会走到这里；一次网络切换最多一次测速（息屏时推迟到亮屏）。#168 的在线识别也只在服务启动或网络签名变化时触发，两接口串行请求并缓存结果；相同签名不重复请求，没有定时器或轮询。

## #168：网络运营商识别与首页常显卡片
- `NetworkRetest` 仍由 `NodeIpNotifier.start()` 幂等启动。启动时识别当前底层网络；网络稳定变化后复用 #24 的 4 秒事件等待，只识别一次。签名未变且缓存签名相同则直接复用，不发请求。
- 识别请求在后台线程执行，并通过 `NetworkIpv6.bestNetwork()` 取得 VPN 之下的非 VPN 网络；两个 HTTPS 请求均使用该 `Network.openConnection()` 绑定底层网络，不经过 Clash VPN 默认路由。接口为 `https://myip.ipip.net` 与 `https://whois.pconline.com.cn/ipJson.jsp?json=true`；连接 / 读取超时各 5 秒，响应体最多 4KB，按响应 charset 解码，未声明时 UTF-8，乱码再尝试 GBK。
- 移动网络先尝试读取默认数据卡 MCC+MNC（API 24+ 通过 `getDefaultDataSubscriptionId()` / `createForSubscriptionId()`，旧版本读取默认 `TelephonyManager`）。不申请 `READ_PHONE_STATE` 等危险权限；系统不允许读取、无卡或运营商码不可用时，记录 `online_fallback` 来源并改走上述在线接口。
- MCC/MNC 分类：移动 46000 / 46002 / 46004 / 46007 / 46008；联通 46001 / 46006 / 46009 / 46010；电信 46003 / 46005 / 46011 / 46012；广电 46015。在线文本关键词同时识别中文和 Unicom / Telecom / Chinanet / Mobile / CMNET / CMCC / Broadcast。不能归类时显示“未知”，本身不算网络错误。
- 两接口都有效但运营商不同，显示未知并记“运营商不一致”；仅一个接口有效时采用该结果；两者均无有效公网 IP 时记请求错误。排除私网、环回、链路本地、组播、100.64.0.0/10 和文档保留地址。网络切换后无网络也会落盘并通知首页。
- 识别结果用 `common/.../NetworkIdentityStore.kt` 的 `AtomicFile` JSON 快照跨进程共享：服务进程单写，首页和错误页读取；避免多进程 `SharedPreferences` 缓存不同步。结果变化后复用 `ACTION_ISSUES_CHANGED` 广播刷新首页。
- 息屏时不发在线请求；当前网络签名暂存，亮屏后补识别。无定时器、无轮询、失败不自动重试；下一次网络签名变化再查。
- **改动文件：** `NetworkRetest.kt`、`NetworkIdentity.kt`、`NetworkIpv6.kt`、`NetworkIdentityStore.kt`、`NetworkIdentityText.kt`；复用 `NodeIpNotifier.kt` 和 `NodeIpEvents.kt` 已有启动 / 广播通道，不新增权限、JNI 或内核补丁。
- **验证与局限：** 本次未运行 Gradle / Kotlin 编译；需用户手动构建并由 Actions 验证。在线接口是否能在目标设备上稳定访问、绑定网络是否确实绕开 Clash VPN、运营商字段实际格式及双卡默认数据卡读取，均需设备实测。无 `READ_PHONE_STATE` 权限时移动卡本地识别可能不可用，会自动走在线接口。
