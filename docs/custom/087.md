## 87. 保留最近一轮 IP 测试结果并合并本地落盘（r331，r338 修正）

- **目标：** 离开“配置检查”页面后再次进入，仍显示最近一轮 IP 测试结果；App 进程重启后也可恢复。只保留最近一轮，不累积历史。
- **保存内容：** 使用配置检查页现有 SharedPreferences 固定键 `ip_test_last`，以单份 JSON 覆盖保存测试模式、目标站模式、域名 / 节点 / 端口 / 下载地址、完整 IP 行数据、机房名称及国家映射、进度和最多 200 行实时日志。日志快照在实际落盘时从当前视图取得并复制为独立列表，不在每条日志到达时复制；新一轮开始和测试参数写入时取消待执行任务并立即落盘。
- **合并落盘：** IP 行、进度、说明、机房映射和日志变化只更新内存状态；最后一次变化后约 2 秒执行一次性延迟落盘。新变化会取消并重排延迟任务。快照仍在主线程取得，JSON 序列化和偏好写入在后台执行；写入串行化并带版本保护，较旧快照不能覆盖较新的快照。说明内容未变化时不重复更新；机房映射未变化时不触发表格重绘。
- **强制落盘：** 一轮 IP 测试结束（包括取消或异常退出）、Activity 进入后台、Activity 销毁、恢复最近一轮结果前，以及离开 IP 测试表切换到文本 / 有效配置 / DNS 页面前，均先取消待执行延迟并完成当前快照落盘。
- **替换：** 新一轮 IP 测试开始时立即用空结果覆盖上一轮；不创建按轮次命名的文件，不追加历史。存储大小只取决于最近一轮结果。
- **恢复：** 重新进入页面时重建原表格、排序、机房显示、进度和日志；恢复行内下载测速所需的测试参数。恢复后不把测试状态或下载状态标记为运行中。
- **保留：** 不改变 IP 测试算法、探测 / 下载请求、测试顺序、表格列和排序、复制、行内测速及取消行为；其他配置检查页面行为不变。
- **改动文件：** `design/src/main/java/com/github/kr328/clash/design/custom/ConfigCheckDesign.kt`、`app/src/main/java/com/github/kr328/clash/custom/ConfigCheckActivity.kt` 和本登记文件；上游文件总表不变。
- **功耗 / 网络：** 仅在用户启动测试或测试状态更新时安排一次性本地延迟任务；不新增周期任务、轮询或网络请求。恢复时只读取本地数据。
- **验证：** 静态核对状态更新、日志快照、延迟任务取消 / 重排、强制落盘时机、后台序列化和版本保护；未运行 Android 编译或真机验证。
