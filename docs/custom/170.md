## 170. 订阅更新后显示变更摘要

### 保存上一份配置
- 仅对非 `Profile.Type.File` 的订阅，在 `ProfileProcessor.update()` 和 `ProfileProcessor.apply()` 即将覆盖 `importedDir/<uuid>/config.yaml` 前保存当前旧文件。
- 每个订阅只保留一份，后续更新覆盖上一份；放在 `filesDir/custom/config_update_snapshot/<uuid>.yaml`。
- 旧文件为空、缺失或超过 4 MiB 时不保存，并删除该订阅可能存在的旧副本，避免显示过期差异。
- 订阅删除时同步删除副本。副本不进入本地或云端备份。
- ProfileProcessor 只增加挂钩；复制逻辑在独立的 `ConfigUpdateSnapshot.kt`。

### 错误与诊断页
- `ErrorsActivity` 创建时，在 IO 线程读取当前订阅的旧副本和当前 `config.yaml`，只计算一次；返回前台、刷新、后台更新和定时过程不重新计算。
- 使用 design 模块已有的 `ConfigDiff.diff`，不调用 service 模块中的 YAML 解析器，也不新增解析器。
- `ErrorsReport` 增加可空的 `subscriptionUpdate: SubscriptionUpdateDiff?` 字段，由 `ErrorsActivity` 在页面创建时计算一次并传入；`ErrorsText` 只在字段非空时显示摘要。
- 仅显示一行“订阅更新：新增 N 行、删除 N 行”。统计按行：新增数 = ADDED + CHANGED，删除数 = REMOVED + CHANGED；无变化、无副本或读取失败时不显示。
- 该信息仅进入错误与诊断页文字，不计入首页问题数。
- 不尝试区分 `proxies` / `rules`，不显示节点数。

- 修改：`ProfileProcessor.kt`、`ErrorsActivity.kt`、`ErrorsReport.kt`、`ErrorsText.kt`、`CUSTOM.md`。
- 不改备份格式、mihomo、`IpTestDialog.ask`。

### 验证与局限
- 本次仅做源码静态核对；未运行 Gradle / Kotlin 编译，需由用户手动构建并由 Actions 验证。
- `ConfigDiff` 是按缩进树做文本行比较，不是 YAML 语义比较；差异摘要明确以“行”为单位。
