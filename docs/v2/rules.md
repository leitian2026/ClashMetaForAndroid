# 修改规范

## 合并友好
1. 新功能优先新增文件、类或页面，不重写上游已有逻辑。
2. 必须改上游文件时，只加最少几行挂钩；真正逻辑放在新文件里，挂钩处加 `CUSTOM` 注释，方便搜索。
3. 不格式化、重命名、移动、重排上游代码，不顺手优化无关部分。
4. 字符串和资源放进独立的新文件，不往上游资源文件里插行。
5. 提交信息写 `custom #N：简述`，功能之间互不依赖。
6. 需要对照 mihomo 内核源码时，先给用户下载地址，由用户提供源码；不凭记忆或猜测对照。

## 功耗规范
**禁止：**
- `Timer`、`Handler.postDelayed` 循环、`while` 加 `delay` 轮询、`AlarmManager`、周期性 `WorkManager`。
- 息屏或后台做无人需要的工作；失败后自动无限重试。
- 整表重建、遍历视图树、重复测量、重复解析同一份数据。

**必须：**
- 一切事件驱动，只由用户操作、系统广播或核心回调触发。
- 息屏停止刷新界面和测速查询；亮屏只补一次最新状态。
- 网络请求只能由用户操作或网络变化触发。
- 只更新发生变化的那一项。
- 每个操作前先考虑计算量；大文件、长列表分批处理或只处理可见部分。
- 拿不准是否需要执行，默认不跑。

## 缓存规范
- **默认用缓存。**
- **没有时效性的缓存**（数据本身不会变，或变化时能确定地让缓存作废，例如同一份数据的排序、解析结果、国旗图、固定解析规则、补全词库）：直接缓存，不用问用户。
- **有时效性的缓存**（数据会随时间、网络、配置或节点变化，旧值会使结果不准，例如当前 IP、运营商、落地国家、延迟、测速结果、域名解析结果、失败请求结果）：必须先让用户选择，AI 不得自行决定。
- 询问每项有时效性缓存时，必须说明：缓存什么、何时会变化、旧缓存最坏会显示成什么；列出“不缓存 / 仅在指定事件时作废 / 按时间过期并给出时长 / 事件加时间并用”各自的结果和功耗收益；给出推荐，但由用户决定。
- 用户选定的缓存策略写入 `changes.md` 对应功能行后面，以后不能擅自更改。
- 不确定是否有时效性，按有时效性处理，先询问用户。

## 测试规范
1. 新增或修改功能时，纯逻辑（不依赖 Android 的匹配、解析、比较、合并、策略判断等）必须在 `tests/custom/` 增加或更新测试；测试源文件必须同时列入 `scripts/run-custom-tests.sh` 和 `.github/workflows/test-custom.yaml` 的 `push.paths`（`scripts/check-custom.sh` 会检查这两处是否一致）。
2. 逻辑依赖 Android 时，优先把纯逻辑提取到独立 Kotlin 文件，再为它编写测试；提取时只搬代码、不改逻辑，参考 #171 的 `CarrierSwitchMatcher.kt`。
3. 不增加 Gradle 测试依赖或 Android stubs。UI、通知、网络请求及 Android 框架行为不纳入 JVM 测试，需说明并手动验证。
4. 修改已有纯逻辑时，必须在同一次提交更新对应测试。测试发现可疑的既有行为时，保留原行为并报告，不擅自改变规则。
5. 纯 UI 或不含纯逻辑的挂钩可以不加测试，但要说明原因。
6. `docs/v2/changes.md` 对应功能行末尾注明 `测试：<测试文件名>`。
7. 测试只在 CI 中运行，不打进 APK，不增加 App 体积或运行功耗。
8. 交付时说明新增或更新了哪些测试，以及哪些部分无法自动测试。
9. 既有功能不要求追溯补测试；以后修改其纯逻辑时再补。

## 文档与登记
- 新文档只记录三类内容：合并上游所需信息、修改文件的规范、每个功能改了什么（一两句话）。不记录实现思路、调试过程、选择原因或版本流水。
- `docs/v2/upstream.md`：每个改过的上游文件一行，写对应功能编号、风险和冲突恢复方式；复杂步骤放在该文件的“细节”小节。
- `docs/v2/rules.md`：本文件，统一维护修改规范。
- `docs/v2/changes.md`：每个功能编号一行，写一两句话；已删除功能标注“已删除”。只新增文件、未改上游文件的功能也要登记。
- 每次改功能，同一次提交更新受影响的 `upstream.md` 行和 `changes.md` 对应行；新功能使用已有编号，找不到编号先问用户，不得自行编号。
- 文档不写过程流水，不追加“又改了什么”，始终原地更新为当前事实。
- `CUSTOM.md` 只保留“基线：”和“当前版本：”两行作为元数据；构建脚本和工作流读取“当前版本：”，不得删除或移走这两行。除此之外不再往 `CUSTOM.md` 写内容。
- 旧文档位于 `CUSTOM.md`、`CUSTOM_ARCHIVE.md` 和 `docs/custom/`，只允许合并上游时按需查阅，不得作为修改代码或编写新文档的依据，也不得继续写入正文。
